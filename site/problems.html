Files and permissions

Permission denied when running a script

-bash: ./deploy.sh: Permission denied

What you see

Running a script with ./name fails even though you own the file.

Why it happens

  • The file has no execute bit (-rw-r--r--)
  • The file system is mounted noexec (/tmp often is)
  • A directory on the path is not searchable for you

Confirm it

ls -l deploy.sh
findmnt -no OPTIONS --target deploy.sh

Fix it

  • chmod u+x deploy.sh # or 755
  • bash deploy.sh # runs it once without the bit

Prevent it

Commit scripts with the bit set (git update-index --chmod=+x). Never use 777: it lets anyone rewrite what runs.

Files and permissions

bad interpreter: No such file or directory

-bash: ./deploy.sh: /bin/bash^M: bad interpreter: No such file or directory

What you see

A script fails with an interpreter error although /bin/bash exists.

Why it happens

  • Windows line endings (CRLF): the kernel looks for "/bin/bash\r"
  • The shebang names an interpreter that is not installed

Confirm it

file deploy.sh   # with CRLF line terminators
head -1 deploy.sh | od -c | head -2

Fix it

  • sed -i 's/\r$//' deploy.sh
  • sudo apt install dos2unix && dos2unix deploy.sh

Prevent it

Add *.sh text eol=lf to .gitattributes, and set your editor to LF for scripts.

Files and permissions

EACCES: permission denied in a service's log

Error: EACCES: permission denied, open '/srv/shop/uploads/receipt-8813.pdf'

What you see

A service runs but cannot read or write a file or folder.

Why it happens

  • Files created by root with sudo (tar, cp, git pull) in the app's folders
  • A secret tightened to root-only that the service reads itself
  • The service runs as a different user than you think

Confirm it

systemctl show -p User shop
ls -ld /srv/shop/uploads
sudo -u shop test -w /srv/shop/uploads && echo writable

Fix it

  • sudo chown -R shop:shop /srv/shop/uploads
  • sudo chown root:shop FILE && sudo chmod 640 FILE # for secrets

Prevent it

Run deploy steps as the service user (sudo -u shop ...), not as root.

load average: 2.02, 1.88, 1.53

What you see

Everything is slow; top shows a process near 100% per core.

Why it happens

  • A runaway job or loop
  • Too many workers for the CPUs
  • Load also counts processes waiting on disk (see I/O wait)

Prevent it

Run batch work under limits (systemd-run -p CPUQuota=) or off-peak.

What you see

After killing a process, its output is truncated and it will not start again.

Out of memory: Killed process 2759 (java) total-vm:5832104kB, anon-rss:3201552kB

What you see

A process dies suddenly; the shell prints Killed or the service shows status=9/KILL.

Why it happens

  • The kernel's OOM killer ran out of memory and chose it
  • A cgroup MemoryMax= limit was hit

Confirm it

sudo dmesg -T | grep -i -e 'out of memory' -e oom

Fix it

  • Size the heap or workers to the machine (e.g. -Xmx1g)
  • Add memory, or move one workload away

Prevent it

Set MemoryMax= per service and alert on available memory, not on used.

What you see

Writes fail: logs stop, uploads fail, services crash.

Why it happens

  • The file system is full (df -h)
  • Inodes are exhausted (df -i)
  • Deleted files still held open (lsof +L1)

Fix it

  • Delete or compress what you do not need, truncate runaway logs, restart processes holding deleted files

Prevent it

Alert at 80%, rotate logs by size, keep data on its own volume.

Performance

High load, idle CPU (I/O wait)

%Cpu(s):  5.6 us,  1.4 sy,  0.0 ni,  0.0 id, 81.0 wa

What you see

Load is high, CPUs idle, everything slow.

Why it happens

  • Processes in D state wait on a saturated disk (backup, rsync, updatedb)

Confirm it

top   # wa
vmstat 1 5   # b column
sudo iotop -o
ps -eo pid,stat,cmd | grep ' D'

Fix it

  • sudo ionice -c3 -p PID for the I/O hog, or reschedule it

Prevent it

Run backups with ionice -c3 nice -n19, off-peak, or on a separate disk.

Performance

Swap thrashing

si 1840  so 2210

What you see

Everything, even ssh, is very slow; disk busy.

Why it happens

  • The working set does not fit in RAM

Confirm it

free -h
vmstat 1 5
top -o %MEM

Fix it

  • Cap the hog: sudo systemctl set-property NAME MemoryMax=1G, or stop it

Prevent it

Set MemoryMax= per service; alert on swap-in rate.

Performance

Main process exited, code=killed, status=9/KILL

reports.service: Failed with result 'oom-kill'.

What you see

A service is killed and restarted again and again.

Why it happens

  • The OOM killer, a MemoryMax= limit, or someone's kill -9

Confirm it

journalctl -u reports | grep -i -e oom -e kill
sudo dmesg | grep -i oom

Fix it

  • Fit the service to memory (heap, workers), or give it more

Prevent it

Never protect one service with oom_score_adj at the cost of the database.

Performance

Too many open files

accept4() failed (24: Too many open files)

What you see

A busy service refuses connections or cannot open files.

Why it happens

  • The service's open-files limit (1024 by default)
  • A file descriptor leak

Confirm it

cat /proc/$(pgrep -o gateway)/limits | grep 'open files'
ls /proc/$(pgrep -o gateway)/fd | wc -l

Fix it

  • Drop-in [Service] LimitNOFILE=65535, daemon-reload, restart

Prevent it

limits.conf does not apply to services: set LimitNOFILE= in the unit.
